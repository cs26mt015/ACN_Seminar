# Let's start with 1. What is a Network?

Don't worry about B4 for a moment.

Suppose you have:

```text
Laptop A  ─────────  Laptop B
```

You want Laptop A to send a file to Laptop B.

The two computers need some way to communicate.

That's a **network**.

More generally:

> **A computer network is a collection of connected devices that can communicate and exchange data.**

For example:

```text
Laptop
   │
   │
Phone ─── Switch ─── Server
   │
   │
Printer
```

The devices could be:

* laptops
* phones
* servers
* printers
* switches
* routers
* etc.

The important idea is:

**Network = connected devices + communication**

---

# 2. What actually travels through a network?

This is very important for B4.

When you send something across a network, the entire file doesn't simply travel as one giant object.

Data gets broken into smaller units called **packets**.

For example:

```text
Large file

        ↓

┌────────┐
│Packet 1│
├────────┤
│Packet 2│
├────────┤
│Packet 3│
├────────┤
│Packet 4│
└────────┘
```

Those packets travel through the network.

Conceptually:

```text
Computer A
    │
    │ Packet
    ↓
  Network
    │
    ↓
Computer B
```

This is why you'll constantly hear the word **packet** in networking papers.

B4 is fundamentally about moving huge amounts of network traffic between Google's data centers.

---

# 3. Switch

Now imagine we have several computers:

```text
PC1 ──┐
PC2 ──┤
PC3 ──┤── Switch
PC4 ──┘
```

A **switch** connects devices within a network and forwards Ethernet frames toward the appropriate destination.

For now, remember:

> **Switch = connects devices and forwards traffic within a network.**

A simplified example:

```text
PC1 ──┐
PC2 ──┤
PC3 ──┤── SWITCH
PC4 ──┘
```

PC1 wants to communicate with PC3.

The switch receives the frame from PC1 and forwards it toward PC3.

---

# 4. Router

Now suppose we have **two different networks**.

```text
Network A                    Network B

PC1 ── Switch ── Router ── Switch ── PC2
```

The router connects different networks.

So a very useful beginner distinction is:

| Device     | Basic job                                                                |
| ---------- | ------------------------------------------------------------------------ |
| **Switch** | Connects devices/networks at the local network level and forwards frames |
| **Router** | Connects different IP networks and forwards packets between them         |

Don't worry about all the details yet.

We'll eventually need to understand exactly **how a router decides where a packet goes**.

That's where **routing tables** come in.

---

# 5. LAN

Now take a group of devices in one location:

```text
       PC
        │
PC ── Switch ── Printer
        │
      Server
```

This could be a **LAN — Local Area Network**.

Think:

> **LAN = network covering a relatively local area, such as a building, office, campus, or data-center environment.**

---

# 6. WAN

Now connect networks that are geographically far apart.

```text
       WAN
       
Data Center A
      │
      │
      ├──────────────┐
      │              │
      │              │
      │              │
Data Center B    Data Center C
```

That's a **WAN — Wide Area Network**.

Think:

> **LAN → local**
>
> **WAN → connects networks over large geographic distances**

And **this is where B4 starts becoming relevant.**

The B4 paper describes Google's private WAN as a network connecting its data centers around the planet. 

The paper also distinguishes B4 from Google's user-facing WAN: B4 is specifically used to provide connectivity **among data centers**, including things like data copies, index pushes, and data replication. 

So visualize B4 like this:

```text
                 GOOGLE B4 WAN

       ┌──────────── WAN ────────────┐

       │                             │
       ↓                             ↓

┌─────────────┐                ┌─────────────┐
│ Data Center │                │ Data Center │
│     A       │                │     B       │
└─────────────┘                └─────────────┘
       │                             │
       │                             │
       └───────────┐     ┌───────────┘
                   │     │
              ┌────▼─────▼────┐
              │ Data Center C  │
              └───────────────┘
```

The interesting part is:

**How does Google decide which path traffic should take between these data centers?**

That question leads us to **routing**.

# 7. Data Center

Before routing, one more concept.

A **data center** is basically a facility containing a large number of computing and networking resources:

```text
              DATA CENTER

       ┌───────────────────────┐
       │                       │
       │  Server Server Server │
       │  Server Server Server │
       │  Server Server Server │
       │                       │
       │  Switches / Network   │
       │                       │
       └───────────────────────┘
```

Google has many data centers.

Applications and services run across these facilities.

The B4 paper says Google's data-center applications generate large amounts of traffic between sites, including data replication, remote storage access, and large-scale synchronization. 

So we now have:

```text
Data Center A
      │
      │
      ↓
     WAN
      │
      ↓
Data Center B
```

# 8. Now the important question: Routing

Suppose:

```text
A ─── B ─── D
 \          /
  ─── C ───
```

A wants to send a packet to D.

There are multiple possible paths:

```text
Path 1:

A → B → D


Path 2:

A → C → D
```

Who decides which path to use?

**Routing.**

Routing is essentially about determining paths through a network.

A routing protocol helps network devices learn about available paths and reachability.

We'll later study protocols such as:

* BGP
* ISIS

because **B4 actually uses them**. The paper says its server clusters run BGP and that B4 also uses ISIS/BGP as part of its routing system. 

---

# 9. But here's where B4 becomes interesting

Imagine this:

```text
             ┌────── B ──────┐
             │               │
Data Center A                Data Center D
             │               │
             └────── C ──────┘
```

Suppose:

```text
Path A → B → D
```

is currently very busy.

But:

```text
Path A → C → D
```

has spare capacity.

A traditional routing approach may choose a path according to its routing rules.

But Google wants something more sophisticated:

> **"How can we distribute traffic across multiple paths according to application demand, priority, and available capacity?"**

That is **Traffic Engineering (TE)**.

The B4 paper explicitly describes its TE goal as sharing bandwidth among competing applications, potentially using multiple paths. 

And this is one of the central ideas we'll eventually need to understand.

---

# 10. The final big concepts

We're eventually going to connect:

```text
ROUTING
   │
   ├── "Where can packets go?"
   │
   ↓
FORWARDING
   │
   ├── "Which action should this packet take NOW?"
   │
   ↓
TRAFFIC ENGINEERING
   │
   ├── "How should we distribute traffic across
   │     the available network?"
   │
   ↓
SDN
   │
   ├── "Can software centrally control this?"
   │
   ↓
OPENFLOW
   │
   ├── "How can that software program the switches?"
   │
   ↓
B4
```

That last chain is **the heart of your seminar**.

B4 uses an SDN architecture in which switches primarily forward traffic while control functionality runs on servers; OpenFlow is used to communicate forwarding instructions to the switches.
