# 2. The most important distinction

You need to understand these two terms:

### SDN

**Software Defined Networking** is the **architectural idea**.

It separates:

```text
Control
  │
  │ "What should happen?"
  ▼
Forwarding
  │
  │ "Actually move packets"
  ▼
Network hardware
```

### OpenFlow

**OpenFlow is a mechanism/protocol used to communicate forwarding instructions to switches.**

So:

```text
SDN = architecture / design approach

OpenFlow = mechanism used to program switches
```

They are **not the same thing**.

For B4, the paper says its architecture uses SDN principles and OpenFlow to manage individual switches.

# ⭐ Professor Question #1

### "Are SDN and OpenFlow the same?"

Answer:

> **"No. SDN is the broader architectural concept of separating control from forwarding. OpenFlow is a protocol/interface that can be used to control forwarding devices in an SDN architecture."**

That's a strong answer.

# ⭐ Professor Question #2

### "Why does centralized control help B4?"

Answer:

> **"Because B4 wants to optimize traffic across the WAN as a whole. A central Traffic Engineering service can consider network-wide capacity and application demands instead of making independent decisions at each site."**

The paper's architecture specifically enables central control of the entire network through the site-level control components.

     ▼

     ▼

# 🧠 Control Plane vs Data Plane

You should now add this to your seminar notes.

### Control plane

> **Decides what the network should do.**

Examples in B4:

* Routing
* Traffic Engineering
* Network state
* Forwarding decisions

### Data plane

> **Actually forwards packets.**

Examples:

* Switch forwarding tables
* Packet lookup
* Packet transmission

So:

```text
       CONTROL PLANE
       "WHAT TO DO?"
             │
             ▼
      forwarding rules
             │
             ▼
        DATA PLANE
      "DO IT / FORWARD"
```

# ⚠️ One subtle B4 point

Don't present B4 as:

> "Google replaced all routing with one centralized controller."

That is **incorrect**.

B4 actually retained traditional routing protocols such as **BGP and IS-IS**, and layered centralized Traffic Engineering on top. 

This is an important design decision.

We'll cover that properly on the architecture slide.
