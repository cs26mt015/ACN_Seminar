### 2. Understand each layer

Layer 1 — Global layer: the decision-maker

It contains two important components:

* Central TE Server: Calculates how traffic should be distributed across available paths, considering bandwidth demands and priorities.

* SDN Gateway: Acts as the bridge between the TE Server and the network controllers. It hides low-level OpenFlow and switch-hardware details from the TE Server.

Think of the TE Server as a manager deciding how to distribute work, while the SDN Gateway communicates those decisions to the teams doing the work.

2486001.2486019.pdf

Layer 2 — Site controller layer: the local coordinator

Each site has Network Control Servers (NCS) that host two important components:

* OFC — OpenFlow Controller: Maintains network state and instructs switches to update their forwarding tables.

* NCA — Network Control Application: Provides network-control functionality and directives used by the controller.

In simple terms, this layer takes network-control decisions and helps turn them into instructions for the switches.

2486001.2486019.pdf

Layer 3 — Switch hardware layer: the packet mover

This layer contains the physical switches that forward network traffic. The switches use forwarding tables to decide where packets should go. The OpenFlow Agent (OFA) receives control instructions and helps apply them to the switch hardware.

The important idea is that the switches primarily forward traffic rather than running all the complex network-control software themselves.

2486001.2486019.pdf

### 3. How the layers work together

Imagine Google needs to send data from Data Center A to Data Center B.

1. The Central TE Server calculates how traffic should be distributed across available paths.

2. The SDN Gateway passes the relevant configuration toward the site controllers.

3. The OpenFlow Controller communicates the required forwarding changes to the switches.

4. The OpenFlow Agent helps program the switch hardware.

5. The switches forward packets using their installed forwarding rules.

The key point: the central server decides how traffic should flow; the switches do the actual packet forwarding. The TE Server does not need to handle every packet itself.

This flow is simplified for learning; the paper's implementation includes additional details for routing, switch state, and control communication.

### 5. Questions your professor may ask

Q1. Why does B4 use three layers?

To separate responsibilities: network-wide traffic decisions, site-level control, and actual packet forwarding. This makes the system easier to coordinate and manage.

Q2. Does “centralized” mean there is only one physical server?

No. The global applications are logically centralized but replicated across multiple physical servers and WAN sites. Leader election selects a primary instance, improving fault tolerance.

2486001.2486019.pdf

Q3. What is the difference between the OpenFlow Controller and OpenFlow Agent?

* OFC: A software component running on a Network Control Server that controls switch behavior.

* OFA: A component associated with the switch that receives control instructions and helps program the hardware.

Easy way to remember: OFC sends the instructions; OFA helps apply them.

Q4. Does the Central TE Server forward packets?

No. It calculates traffic-distribution decisions. The switches forward the packets according to the rules installed in their forwarding tables.

Q5. What happens if the traffic-engineering system has a serious problem?

B4 was designed so that traffic engineering could be disabled and the network could fall back to shortest-path forwarding. The paper calls this the “big red button.”
