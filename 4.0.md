# Slide 6 — B4 Architecture

Now we can finally show the **real architecture**.

## Title

### **B4 Architecture**

Use three horizontal layers:

```text
┌─────────────────────────────────────────┐
│              GLOBAL LAYER               │
│                                         │
│       Central TE Server                 │
│              │                          │
│         SDN Gateway                     │
└────────────────────┬────────────────────┘
                     │
┌────────────────────▼────────────────────┐
│          SITE CONTROLLER LAYER           │
│                                         │
│        Network Control Servers           │
│          │             │                │
│         OFC           NCA               │
└────────────────────┬────────────────────┘
                     │
┌────────────────────▼────────────────────┐
│             SWITCH LAYER                │
│                                         │
│       OpenFlow Agent (OFA)              │
│              │                          │
│       Forwarding Tables                 │
└─────────────────────────────────────────┘
```

### Remember:

**Global → Site Controller → Switch**

The paper describes the global layer as logically centralized applications such as the SDN Gateway and central TE server, with replication across sites. The site layer contains network control components, while the switch layer uses an OpenFlow agent to program forwarding behavior. 

---

## One important phrase

Say:

> **"Logically centralized does not mean physically one machine."**

Why?

Because B4 replicated its global services for fault tolerance and used leader election to choose the primary.

So if the professor asks:

> "Is there only one TE server?"

Answer:

> "No. The service is logically centralized but replicated across multiple physical servers for fault tolerance."

Excellent professor-level detail.
